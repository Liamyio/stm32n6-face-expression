# STM32N6 端侧双模型部署：人脸检测 + 表情识别

在 STM32N647（STM32N6 系列，Cortex-M55 + Neural-ART NPU）上完成双模型级联推理的端侧部署：IMX335 摄像头采集画面，先由人脸检测模型定位人脸，裁剪缩放后送入表情识别模型分类，全程在端侧实时运行，约 10 FPS。本仓库呈现的是完整的部署工程：模型选型与级联设计、INT8 量化与 NPU 调优、片上/片外内存规划、摄像头链路集成与整机验收。

- **硬件平台**：正点原子 STM32N647 开发板（800 MHz，32 MB NOR Flash + 32 MB HyperRAM），IMX335 MIPI CSI-2 摄像头，ST-LINK/V3
- **人脸检测**：RFB-320（Ultra-Light 开源人脸检测模型家族），INT8 量化版 413 KB
- **表情识别**：ResNet18，7 类表情（Anger / Disgust / Fear / Happiness / Neutral / Sadness / Surprise），INT8 量化版 941 KB

## 系统链路

```
IMX335 (MIPI CSI-2, 800×480 BGGR10)
  → DCMIPP Pipe2 + ISP（去马赛克 / AWB / 曝光）
  → RGB565 帧（HyperRAM 双缓冲）
  → 人脸检测 RFB-320 INT8（320×240 输入，NPU）
  → 人脸框映射回原图 → 裁剪 → 双线性缩放 224×224 → RGB888
  → 表情识别 ResNet18 INT8（NPU）
  → UART 输出：帧号 / 人脸框 / 置信度 / 表情与概率
```

两个模型各初始化一次、常驻复用；无脸帧只跑检测（约 12 ms），有脸帧才触发第二级。

## 部署工作要点

- **级联架构与检测模型选型**：PC 端原型用 Haar 级联检测，迁到 MCU 上速度不达标；改选 Ultra-Light 家族的 RFB-320 并量化部署，检测约 12 ms，腾出的算力给第二级表情模型，整帧压到 84～101 ms。
- **量化策略**：表情模型最初的量化模式下 NPU 几乎闲置（51 个 epoch 中 49 个在 CPU 软件执行）；改为静态 QDQ INT8 量化后 54/54 epoch 全部落到 NPU。人脸模型同步完成静态量化（HW epoch 由 2 增至 52）。详见下方对比表。
- **内存规划**：两份模型权重放外部 NOR Flash 分区 XIP 执行（人脸 0x70200000、表情 0x70300000）；激活缓冲按内存池规划——人脸模型激活内存由 FP32 的约 6 MB 压到约 640 KB，全部放进片上 SRAM，帧缓冲与大块中间量走 HyperRAM 双缓冲。
- **摄像头链路集成**：IMX335 经 MIPI CSI-2 接入 DCMIPP Pipe2，ISP 完成去马赛克、自动白平衡与曝光；检测框坐标映射、裁剪、双线性缩放与 RGB888 转换全部在端侧完成，再按表情模型的输入规格（224×224、归一化）喂入第二级。
- **运行时结构**：双模型各初始化一次后常驻，逐帧只重建必要的推理上下文；UART 逐帧输出帧号、人脸框、置信度与表情概率，便于 PC 端脚本对齐验证。

## 实测性能（板端验收记录）

| 指标 | 数值 |
|---|---|
| 人脸检测推理 | 约 12 ms |
| 表情识别推理 | 约 15 ms（生成报告口径）；含逐帧上下文重建约 37 ms |
| 整帧总耗时（有脸） | 84～101 ms，约 10 FPS |
| 真人正脸检测分数 | 0.996 |
| 人脸模型激活内存 | 约 6 MB（FP32）→ 约 640 KB（INT8，全部放进片上 SRAM） |

## 量化前后对比（ST Edge AI 分析口径）

| 模型 | 量化前 epoch 分布 | 静态 QDQ INT8 后 |
|---|---|---|
| 表情 ResNet18 | SW 49 / 51（96.1%），HW 仅 1 / 51 | **54 / 54 全部 HW** |
| 人脸 RFB-320 | SW 100 / Hybrid 6 / HW 2 | **HW 52 / Hybrid 12 / SW 1** |

模型体积：表情模型 44.7 MB（FP32）→ 941 KB（INT8）；人脸模型 INT8 版 413 KB。

- 表情识别模型为团队自训成果，**其权重与 ST Edge AI 生成代码未在本仓库公开**；`03_表情模型INT8生成产物/` 与 `01_双模型主工程/Appli/Models/expr_net/` 仅保留生成报告（含 epoch 分布与内存统计）和接口头文件。
